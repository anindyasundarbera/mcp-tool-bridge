# MCPB-004 — Isolated asynchronous development

## Decision

Every `send_to_local_dev` call now creates an in-memory asynchronous job and
runs Claude in a bridge-created detached Git worktree. The configured checkout
must be clean immediately before worktree preparation and must remain at the
same `HEAD`. The call returns an opaque job ID instead of waiting for Claude.

Three lifecycle tools inspect, resume, or cancel that job. Job records survive
for the lifetime of the server; worktrees survive terminal outcomes and server
restarts so MCPB-005 can verify and commit reviewed candidates.

## Contracts

```text
send_to_local_dev(project_id, text, effort="high")
get_development_job(project_id, job_id)
resume_development_job(project_id, job_id, text, effort="high")
cancel_development_job(project_id, job_id)
```

- A job ID is exactly 32 lowercase hexadecimal characters generated by the
  bridge.
- Status flows through `queued`, `preparing_worktree`, `running`, optionally
  `validating_candidate`, and a terminal state.
- Terminal states are `completed`, `failed`, `timed_out`, and `cancelled`.
- Results omit absolute source/worktree paths and the raw Claude session ID.
- Resume accepts only a job ID. It reuses the retained worktree and passes the
  session ID captured from that job exactly once through a fixed command vector.
- Cancellation terminates the process group and retains candidate files.

## Worktree security invariants

1. Resolve exact `project_id` and `claude_edit` authorization first.
2. Require an empty porcelain Git status, including staged and untracked files.
3. Record exact source `HEAD` and create
   `JOB_WORKTREE_ROOT/<project_id>/<job_id>` with `git worktree add --detach`.
4. Reject a worktree root inside or above a project root, any symlink/non-
   directory component, group/world-accessible final root, and path collision.
5. Require the created worktree to be clean, detached, rooted at its controlled
   path, and at the recorded base HEAD.
6. Recheck source cleanliness and HEAD after creation.
7. Use fixed Git argument vectors, bounded timeouts, and no shell.
8. Never create/update a branch or ref; never stage, commit, push, merge, tag,
   promote, restart, or delete a retained candidate.

Markdown writes and all job attempts share one per-project modifying lock.

## Claude and continuation boundary

Claude retains `acceptEdits` with `Read,Glob,Grep,Edit,Write`. Bash, web,
secondary MCP tools, slash commands, and `bypassPermissions` remain disabled.
The executor now accepts an internal worktree root and optional stored session
ID. Public schemas expose neither value. Timeout and cancellation terminate the
complete process group.

Continuation is allowed only when the prior job is terminal, its bridge-
captured session is valid, its worktree still exists at the original detached
HEAD, and the source checkout is clean at its original base HEAD.

## Self-managed candidate boundary

Self-managed projects may enable isolated `claude_edit` but still cannot enable
direct `markdown_write`. After a successful run, the candidate server is
started temporarily with the current Python interpreter on
`127.0.0.1:CANDIDATE_MCP_PORT`. A local FastMCP client initializes it, lists
tools, and requires the MCPB-004 lifecycle surface. The candidate process is
always stopped after the bounded probe. Its environment is an explicit minimal
allowlist and excludes tokens, certificates, ngrok settings, and arbitrary
production environment variables.

Health results contain only status, port, tool names, and bounded diagnostics.
A healthy candidate is retained for review but never becomes production.

## Configuration

| Setting | Default |
|---|---:|
| `JOB_WORKTREE_ROOT` | `~/.local/state/local-dev-mcp/worktrees` |
| `GIT_COMMAND_TIMEOUT_SECONDS` | `30` |
| `CANDIDATE_MCP_PORT` | `8001` |
| `CANDIDATE_HEALTH_TIMEOUT_SECONDS` | `30` |

The candidate port must differ from `MCP_PORT`.

## Deferred to MCPB-005 or later

- Fixed verification commands and diff fingerprints
- Exact authorized staging paths and commits
- Candidate promotion, production restart, rollback switching, merge, push,
  tags, and branches
- Worktree deletion through MCP
- Arbitrary session IDs, unrestricted Bash, or arbitrary shell commands
