Capability elevation map · 2026-08-10

BridgeLab → Super Developer Level

An open-source scan of the MCP / agentic-dev / sandbox / supply-chain ecosystem, mapped onto BridgeLab's own 149-item capability roadmap — the patterns worth adopting, in the order that unblocks the most.

BridgeLab v0.10.0 (MCPB-010, PR #5) 44 done · 53 partial · 52 missing 33 milestones research via GitHub API + SearXNG

Context

What BridgeLab is, and the shape of the gap

BridgeLab (anindyasundarbera/mcp-tool-bridge) is an MCP bridge: ChatGPT reaches it over an ngrok+mTLS tunnel and drives a local Claude Code CLI to do isolated engineering on the user's own allowlisted projects. Its spine is a security discipline, not a feature list — validated multi-project registry, detached-git-worktree isolation per job, fixed-argv verification (no shell), SHA-256 candidate fingerprints, separate human-approved commits, opt-in non-trunk push, durable SQLite state with resumable checkpoints, soft/hard turn budgets, and an append-only job event ledger.

A 12-agent audit (recorded in docs/MCPB-ROADMAP.md) scored all 149 capability items against the source: 44 done, 53 partial, 52 missing — 105 open. MCPB-010 closed the P0 continuity core. Most of P1 (evidence, requirements, orchestration), most of P2 (verification lab, governance, security, recovery), and all of P3 remain. The question this report answers: which open-source projects already solve these gaps in a way BridgeLab can adopt without breaking its security spine?

The elevation map

Open-source pattern → BridgeLab milestone

For each milestone cluster, the one pattern worth borrowing, how it fits BridgeLab's additive + lazy-import + zero-surface discipline, what it unblocks, and the security note. Ordered by unblock value, not by roadmap release number.

M-EV-01Requirement traceability — the highest-value single unblock← github/spec-kit

Status: MISSING. No requirements.py, no requirements table; all nine traceability bullets open. This is the named CKS-002B blocker.

Adopt

spec-kit's model is intent → spec (normative requirement IDs) → implementation → tasks, driving any coding agent. Borrow the normative-ID convention and the spec-as-source-of-truth discipline: a RequirementManager(settings, store, reader) extracts IDs (default pattern ^[A-Z]+-\d+[A-Z]?-R\d+ plus fenced normative blocks), classifies normative vs example/commentary, and joins requirements → requirement_links → changed paths / test names into a coverage matrix. Additive requirements + requirement_links tables; SCHEMA_VERSION stays 1. Internal-first — surface requirements_covered in existing snapshots, no new tool. A coverage-report tool is NEW SURFACE.

M-CT · MCPB-010 tailResumable state done better — checkpointers, stores, time-travel← langchain-ai/langgraph

Status: DONE core + PARTIAL tail (M-CT-01/03/04/05). Checkpoints, paused states, compaction, resume all shipped in MCPB-010. The shape can still mature.

Adopt

LangGraph splits durable state into Checkpointers (short-term thread snapshots — what BridgeLab already has) and Stores (long-term cross-thread memory) and exposes time-travel + interrupts + subgraphs as first-class. Borrow the Checkpointer/Store separation: BridgeLab's job_checkpoints is a checkpointer; add a long-term Store for cross-job lessons (the P3 capsule/passport layer, M-IN-01, without building it yet — just the store). Time-travel maps to M-CT-04 atomic-milestone acceptance (a milestone closes when its acceptance paths + command pass; revisiting an earlier checkpoint is the time-travel primitive). All internal, no new tool.

M-CC-09Verification-lab determinism — the hermetic build← Nix · devbox · nextest · Bazel · libfaketime

Status: PARTIAL. _run_command pins LANG/LC_ALL/PYTHONIOENCODING + wall timeout. Missing: pinned toolchain, cached deps, network policy, deterministic clock/TZ/random, flaky detection, baseline comparison, signed results.

Adopt

PIN_TOOLCHAIN via Nix flakes or devbox (Nix without learning Nix) — a per-project lockfile the bridge resolves before running verification, giving bit-for-bit reproducible envs. Flaky detection via deterministic repetitions (nextest's retry-classification model; for Python, pytest-rerunfailures semantics) — run a command's declared-deterministic subset N times, label divergence as infrastructure_status=DEGRADED (feeds M-EV-07). Deterministic env: TZ=UTC, SOURCE_DATE_EPOCH, PYTHONHASHSEED=0, sorted fs iteration, optional libfaketime for a frozen clock. Baseline comparison against the last green verification's fingerprint (CycloneDX SBOM diff). Each is project opt-in, internal, fixed-argv. A replay_verification tool is NEW SURFACE — defer.

M-CC-11 · M-EV-06Evidence bundle + supply-chain attestation← in-toto · SLSA · cosign · osv-scanner · syft

Status: MISSING portable bundle, source classifications, signed manifests, supply-chain scan. Fingerprints + verification/review records + append-only ledger already exist (good foundation).

Adopt

Bundle format: the in-toto ITE-6 Bundle (.intoto.jsonl) — a JSON-Lines file where each line is a DSSE-wrapped in-toto Statement, each independently signed, with no whole-bundle authentication needed. Verifier reads lines, checks each envelope offline, ignores unknown predicates (monotonic). Each record type becomes a distinct predicate under one Statement shell: https://bridgelab.dev/verification/v1 (verification record), .../review/v1, .../ledger/v1 (job_events snapshot), .../sbom/v1. Subject = the content-addressed candidate fingerprint (already exists). Provenance: add a SLSA provenance/v1 predicate (buildType=https://bridgelab.dev/mcp-bridge@v1, externalParameters = fixed argv + base_head + fingerprint, builder.id = bridge version) so jobs are legible to any SLSA-aware consumer.

Signing: sigstore-python's sign_dsse(Statement) → Bundle / verify_dsse(bundle, offline=True) — a project key for offline-first; keyless+Rekor when public transparency is wanted (the inclusion proof is embedded, so verify stays offline). SBOM: CycloneDX with native in-document signatures (JSF) + BOM-Link, embedded as one bundle line — its properties/annotations are the natural home for M-EV-05 sensitivity-classification labels. Drop: classic in-toto layout+links (its inspections run arbitrary commands at verify time — conflicts with no-shell); SPDX (no native signing); W3C VC (no canonical software-dev evidence schema, overkill); OCI/ORAS (a publication channel, not an audit format — optional distribution add-on only).

The export_evidence_bundle tool is NEW SURFACE (capability EXPORT_EVIDENCE_BUNDLE, dormant by default). Sensitivity classification (M-CC-11) gates inclusion; .env/tokens/certs/.venv excluded — already a BridgeLab invariant.

M-GV-06Sub-agent delegation + parent/child task trees← LangGraph subgraphs · crewAI roles · openai-agents handoffs

Status: MISSING. No parent_job_id, no delegation mandate, no delegation records.

Adopt

LangGraph's subgraph primitive is the cleanest fit: a parent job spawns bounded children, each a subgraph with its own state but scoped to the parent's authorized path set ⊆ and capability ⊆. crewAI's role crews model the Planner/Implementer/Reviewer/Evidence-officer split BridgeLab already half-has. openai-agents' handoffs model the replace-worker control (M-CC-08). Add parent_job_id + delegation_mandate_json (mandate/inputs/outputs/authority) to DevelopmentJob; bound children via config.MAX_DELEGATIONS_PER_JOB; record delegation in the authorizations table (delegated_from). Internal-first; a delegate tool is NEW SURFACE — defer.

M-GV-01/02/03/04Durable authorization + named roles + external grounding + spec-gating← OPA/Cedar · crewAI · spec-kit · MCP ToolAnnotations

Status: PARTIAL. Per-call inline evidence re-statement; ProjectCapability is a static flag, not a per-action authorization record. Roles half-built. No external grounding, no spec-gating.

Adopt

Replace inline-evidence re-statement with a durable authorizations table (actor / authority_source / capability / target / issued_at / expires_at / single_use / delegated_from) — the structure OPA and Cedar encode as policy, but BridgeLab can hold it as a plain SQLite table consumed in the same ACID txn as the action it authorizes. crewAI's role pattern formalizes Planner / Evidence-officer / Supervisor as capability-gated invocations on existing infra (not new runtimes) — each read-only (Read,Glob,Grep only). spec-kit's spec-as-source-of-truth + a pinned ratified_spec_commit gives external grounding (M-GV-03) and spec-gating (M-GV-04): genesis jobs require the apex spec ref present and unchanged. MCP ToolAnnotations (destructive/readOnly) is already BridgeLab's gating grammar. Internal-first; no new tool.

M-GV-07Parallel verify + review + conflict reconciliation← LangGraph fan-out/fan-in · Qodo multi-agent review

Status: PARTIAL. Verify and review are independent managers but run sequentially; validate_for_commit accepts one review, no reconciliation.

Adopt

LangGraph's fan-out / fan-in is the pattern: once the candidate is stable, asyncio.gather verify + independent review concurrently. Qodo's multi-agent review (separate review/improve/describe agents with PR-history indexing) is the model for reviewer conflict reconciliation: divergent verdicts trigger a tie-breaker third reviewer with a distinct reviewer_id; the commit gate requires a reconciled pass. Additive reconcile_reviews(review_ids); no new tool.

M-CC-01/02/05PR creation, state confirmation, race-safe idempotency← PyGithub · gh

Status: MISSING. Lifecycle step 13 (open/update draft PR) is explicitly excluded today; no existing-PR discovery, no PR-state confirmation.

Adopt

Primary path: PyGithub (native Python, draft=True on create, no shell — github3.py lacks the draft param, so it's out). Discovery: repo.get_pulls(state="open", head="owner:branch", base=base) — the owner:branch prefix is mandatory; a bare branch name silently returns all PRs. If found, pr.edit(title=..., body=...); else repo.create_pull(..., draft=True). State confirmation via repo.get_pull(n) → .state/.draft/.merged/.head.sha.

No atomic create-if-not-exists exists anywhere — not in the REST/GraphQL API, not in gh pr create (declined in cli/cli #5792), not in the GitHub MCP server. So race-safety (M-CC-05) requires client-side per-branch mutual exclusion (filelock / Redis SET NX) + a re-check after acquiring the lock to close the window where a peer created the PR while you waited. gh CLI fallback (token-less envs): fixed-argv list with shell=False + --body-file to dodge quoting; use gh pr list --head (not pr view, which has documented false-negatives). Never call merge — omit pr.merge() / gh pr merge. Don't add the GitHub MCP server solely for this — it forces an MCP client + transport and still leaves the upsert to you.

Re-stated evidence required; PR base = the job's base branch; surface remote_branch_state + pr_state (M-CC-02). NEW SURFACE, dormant by default.

M-CC-11Prompt-injection defense for repo-ingested content← NeMo-Guardrails · llm-guard (fork)

Status: PARTIAL. Blast-radius reduction in claude.py build_* exists; no systematic injection defense on content the reader ingests.

Adopt

Borrow the spotlighting / data-trust-boundary technique from the prompt-injection literature (fence + delimit untrusted repo content the reader ingests, so model instructions can't ride in file contents). NeMo-Guardrails' programmable rails or a maintained llm-guard fork as the implementation; run it as fixed-argv on reader output, not as a networked service. Keep it internal and opt-in; no new tool surface — it hardens reader.py.

M-EV-05Authority-behind-every-governance-instruction← langfuse · OpenTelemetry

Status: MISSING. job_events is append-only but governance-changing instructions carry no authority ref.

Adopt

Langfuse / OpenTelemetry's span-attribution model — every event carries actor, authority source, scope, timestamp — is exactly the authority-record shape BridgeLab wants. Stamp governance-changing events (status / extension / pause / terminal) with an authority_ref in jobs._record_event; sidecar authority_records + source_classifications (canonical/historical/asserted/observed/tested/inferred/superseded). Internal, no new tool. Composes with M-GV-01 once the authorizations table exists.

M-CC-11Supply-chain gate — severity-gated pre-commit reject← syft · grype · pip-audit

Status: MISSING. No dependency/supply-chain scanning.

Adopt

Recommended 2-tool combo: syft (SBOM gen, fully offline, emits CycloneDX/SPDX — the same SBOM that goes in the evidence bundle) + grype (grype sbom:./sbom.cdx.json --fail-on=high --only-fixed -o json — exit code 2 on any HIGH/CRITICAL finding, the cleanest severity-gated exit of any scanner, no Python-side threshold logic). Both Apache-2.0 single Go binaries, fixed-argv via subprocess.run([...], shell=False), offline DBs downloadable and refreshed on a schedule (not per-commit). Add pip-audit (pip-audit -r requirements.lock --format=json --vulnerability-service=osv --require-hashes) as a Python-native cross-check inside the same gate; reject commit if either reports HIGH/CRITICAL.

Drop: Dependabot (Ruby + Docker, remediation-not-gate) and Snyk (account-gated, cloud-required, closed-contribution — violates the offline + OSS-clean constraints). osv-scanner is viable (--offline-vulnerabilities + --download-offline-databases) but its exit-1-on-any-vuln needs a Python-side severity filter, so grype's native --fail-on is cleaner. Internal, fixed-argv; feeds M-CC-11 and the evidence bundle (the syft SBOM is the M-EV-06 artifact).

M-CC-11Sandboxed execution of repo-controlled scripts← gVisor · nsjail · bubblewrap · Firecracker

Status: PARTIAL. verification_commands run in the candidate worktree (not a true sandbox); repo-controlled scripts run with the bridge's privilege.

Adopt

For repo-controlled verification scripts, run under a lightweight syscall sandbox rather than the bridge's cwd. Lightest-to-embed in a Python subprocess path: bubblewrap (bwrap) or nsjail with --network=none --read-only + a frozen clock; gVisor (runsc) for stronger isolation without a full VM; Firecracker/E2B/Daytona only if a true per-task VM is warranted (heaviest). Project opt-in; fixed argv (the bridge invokes the sandbox runner, not the sandbox script directly). Network policy (none | allowlist) flows from M-CC-09. Internal; no new tool.

How to sequence it

Recommended adoption order

The roadmap already names the unblock priority; this just attaches the open-source pattern to each step. Everything below respects BridgeLab's additive-table + lazy-import + zero-surface discipline and the verbatim security boundaries in AGENTS.md.

  • 1. Merge PR #5 (MCPB-010) — continuity core is done, tested (167 tests), zero new surface. Nothing here depends on open-source adoption.
  • 2. M-EV-01 requirement traceability — borrow spec-kit's normative-ID + spec-as-truth discipline. Additive requirements/requirement_links tables, internal-first. Highest unblock value; directly serves CKS-002B.
  • 3. M-CT-01 / 04 / 05 — finish the continuity tail (fetch+pin base, atomic milestones, the two dormant states). Borrow LangGraph's time-travel primitive for milestone acceptance. Internal.
  • 4. M-EV-02 / 03 / 04 — structured verification result schema, binding completeness, review content-addressing. Foundation for the evidence bundle; no external dep yet.
  • 5. M-CC-09 verification-lab determinism — first open-source adoption that adds a runtime dep: Nix/devbox for PIN_TOOLCHAIN, pytest-rerunfailures/nextest semantics for flaky detection. Project opt-in.
  • 6. M-GV-01 authorization objects — durable authorizations table; OPA/Cedar-shape, SQLite-held. Unblocks M-EV-05 authority records and M-GV-06 delegation records.
  • 7. M-GV-06 delegation + M-GV-07 parallel review — LangGraph subgraphs + fan-out/fan-in; internal, no new tool.
  • 8. M-EV-06 evidence bundle export + M-CC-11 supply-chain — in-toto ITE-6 .intoto.jsonl + SLSA provenance + CycloneDX SBOM, signed via sigstore-python; supply-chain gate syft + grype --fail-on=high + pip-audit. NEW SURFACE — needs your explicit authorization.
  • 9. M-CC-01 PR automation — PyGithub/gh-backed open/update draft PR. NEW SURFACE — needs your explicit authorization.
  • 10. M-CC-11 sandboxing + injection defense — bwrap/nsjail/gVisor for repo scripts; NeMo-Guardrails/llm-guard fork for reader fencing. Internal hardening.
  • 11. P3 / institutional — capsules, passports, dossiers, blind reconstruction. Build the long-term Store first (LangGraph pattern), fill it later. Explicitly a non-goal for the unblock.
Security constraints (unchanged, non-negotiable). No bypassPermissions or unrestricted Bash; no shell=True; fixed argv. Reject hidden/protected/traversal/symlink paths; .env/tokens/certs/.venv never in archives or Git. The only push surface is opt-in push_development_commit (non-trunk, origin-only, no-force); ChatGPT confirmation is the outer authorization gate; the bridge never directly edits its production checkout. Every item above flagged NEW SURFACE needs a new ProjectCapability (with its dependency capability), a ToolAnnotations-registered tool, and must ship off by default. Merge/tag/release/deploy stay prohibited unless you explicitly authorize Option B (M-CC-04) — the bridge ratifies, a human merges.

Research method: hard repository data (star counts, last activity) via the GitHub MCP API on 2026-08-10; qualitative capability patterns via SearXNG reads of each project's docs. Star counts marked "major"/"OSS"/"GitHub" were not resolvable through the repo-qualifier query and are left approximate.
